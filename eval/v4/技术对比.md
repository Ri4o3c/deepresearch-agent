# 多智能体框架选型报告：LangGraph、CrewAI、AutoGen（2026 年 11 月）

## 摘要

三者的根本差异在架构范式：LangGraph 是状态机/图编排，CrewAI 是角色-任务流水线，AutoGen 是对话驱动协作 [1][2][3]。截至 2026 年 11 月，最关键的选型事实是 AutoGen 已于 2026 年 4 月被微软置为维护模式，官方推荐新项目迁移至 Microsoft Agent Framework 1.0 [6][9][29]。因此，需要强流程控制、可审计与持久化的生产系统应选 LangGraph；追求快速原型、角色分工明确的内容生产与研究写作应选 CrewAI；AutoGen 仅建议用于存量维护或实验性探索，新项目不宜作为首选 [6][15][29]。此外，MCP 与 A2A 协议标准化正在削弱框架间的接口壁垒，选型重心已从"功能多少"转向"生态位与治理能力" [29][34]。

---

## 一、三种架构范式：理解差异的起点

三个框架的定位差异不是功能清单的差异，而是对"多智能体如何协作"这一问题的不同回答 [1][2][3]。

**LangGraph——图编排/状态机。** LangGraph 由 LangChain 团队于 2023 年 10 月发布，定位为状态驱动的任务流框架，核心设计理念是显式状态管理与灵活流转控制 [3][4]。其工作流表示为节点与边：节点是 Agent 状态或操作，边是状态转换，支持条件执行、循环与回溯、检查点（Checkpoints）与基于状态的记忆，因而提供三者中最强的流程控制与持久化能力 [1][2][3]。

**CrewAI——角色协作。** CrewAI 是开源 Python 多智能体编排框架，核心理念是"角色化协作"：为每个 Agent 分配角色（Role）、目标（Goal）和工具（Tools），在结构化流程（Process）中接力完成任务 [2][3][5]。其架构是"Agent-Task"模型，Agent 之间通过任务传递而非即时对话协作，目前流程以顺序执行为主，因此灵活性较低，难以处理动态分支或循环 [1][2][3]。

**AutoGen——对话驱动。** AutoGen 是微软研究院开源的多智能体对话框架，支持 Python 与 .NET，采用异步事件驱动架构，让多个可对话 Agent（含人类）通过消息传递、讨论甚至辩论协作，并特别强调代码执行与验证 [2][3][5]。它提供用户 Agent、助手 Agent、工具 Agent 等抽象及"经理分配任务、专家处理、经理汇总"等交互模式；v0.4 重构引入了更健壮的异步消息通信、插件式组件与跨语言协同，整体偏研究与开发平台定位 [2][5]。

一个值得注意的趋势是编排方向正在趋同：图编排成为共同方向——LangGraph 用状态图，Microsoft Agent Framework 用图工作流，Dify 的工作流本质也是图结构，差别在抽象高度而非方向本身 [14]。

## 二、维护状态与商业支持：2026 年的决定性变量

**AutoGen 已进入维护模式。** 这是本次选型中权重最高的事实：AutoGen 已于 2026 年 4 月被微软置为 maintenance mode，不再开发新功能；微软官方推荐新项目改用 Microsoft Agent Framework 1.0（AutoGen 与 Semantic Kernel 合并的统一 SDK，2026 年 4 月 GA）[6][9]。这并非 AutoGen 消亡，而是两条产品线合并为一条 [29]。社区分支 AG2（Apache 2.0）在独立治理下保持活跃开发，但用户基数小于主框架，有资料称其尚未达到稳定的 v1.0，生产就绪度被评为中低 [6][8][9]。

**LangGraph 的商业化路径清晰。** 2026 年 LangGraph 推出 Deep Agents 高层抽象（内置规划、子代理管理，默认代理轮次输入 token 减少 65%）；商业支持为 LangGraph Cloud 托管执行与状态持久化，定价为免费开发者层、$49/月单部署、$99/月五部署，并配套 LangSmith 可观测性 [6][7][8]。

**CrewAI 已独立并具备企业能力。** CrewAI 在 1.14 版本移除了 LangChain 依赖，成为完全独立框架；订阅方面有免费层 200 次 agent 运行/月，$29/月 1000 次、$99/月 5000 次 [7][8]。企业能力包括 FedRAMP High、专属 VPC、Microsoft Entra 与 Okta SSO、基于 Qdrant Edge 的运行时状态检查点；商业平台 AMP 免费层 50 次执行/月，企业版定制定价 [6][11]。规模方面，CrewAI 达到每月 4.5 亿次 agentic workflow（另有资料称过去 12 个月 20 亿次执行、150+ 企业客户）[6][11]。

**社区规模数据存在明显口径差异，需谨慎采信。** 各来源给出的 GitHub stars 不一致：一组为 AutoGen 42,000 / CrewAI 31,200 / LangGraph 12,800（2026 年 4 月），另一组为 AutoGen 35K+ / CrewAI 22K+ / LangGraph 18K+（2026 年 3 月），还有来源称 CrewAI 57,217 stars [7][10][11]。差异可能源于统计时点不同（3 月 vs 4 月）、是否合并统计组织下多个仓库、以及是否计入 fork 或镜像。本报告采信"2026 年 4 月"这一时点的第一组数据作为相对量级参考，理由是时点最新且三者同源统计；但应将其视为量级参考而非精确值。可确认的趋势是 CrewAI 增长极快：从 2024 年 1 月的 2,800 stars 增至 2026 年 4 月的 31,200（+1,014%）[11]。资料未给出三者统一的精确最新版本号 [7][10][11]。

## 三、关键功能维度对比

**编排能力。** LangGraph 2.0（2026 年 4 月发布）采用真正的状态机范式，支持有向图、条件路由、并行节点、循环执行和 Human-in-the-Loop 节点，被评价为当前编排能力最完整的开源方案；CrewAI 以"角色-任务-流程"三要素抽象，上手成本最低，10 行 Python 即可定义完整多 Agent 协作流程；AutoGen 采用对话+代码执行模式，Agent 间可互相质疑纠错 [15]。

**状态管理。** LangGraph 通过 TypedDict 定义显式状态（State），所有节点共享并修改同一份结构化数据，被认为是目前生产级 Agent 编排中最成熟的上下文共享实现；CrewAI 的 context 参数仅传递前序 Task 的文本输出，结构化程度较低 [15]。

**人机协同（HITL）。** LangGraph 提供 checkpoint/checkpointer、interrupt、resume 等运行时机制，可在节点内部显式暂停并把待审批内容返回外部，人类决策后通过 `Command(resume=...)` 恢复同一执行线程；需注意这些属于框架 API 语汇而非行业统一标准 [15][16]。资料未给出 CrewAI、AutoGen 的 HITL 具体机制，此处存在信息缺口。

**工具调用与可观测性。** MCP 标准化了工具连接、A2A 标准化了 Agent 间通信，框架壁垒正从接口层转向治理层；LangGraph 配合 LangSmith 提供全链路可观测性，是当前生产就绪度最高的方案；AutoGen 内置 Docker 沙箱保障代码执行安全 [14][15]。资料未提供 CrewAI 在工具调用与可观测性上的具体能力描述，此处同样存在缺口。

**性能、调试难度与学习成本：资料不足。** 研究笔记中该子问题的资料实际涉及的是后端 Web 框架、Python 框架、小程序框架、边缘 AI 框架等无关领域（如 TechEmpower 基准、FastAPI、小程序框架测评），无法用于三个多智能体框架的对比 [17][18][21][24][25]。笔记中几乎没有针对 LangGraph/CrewAI/AutoGen 的直接、可量化的性能与学习成本对比数据 [17]。本报告如实说明这一缺口，不以无关内容填充。可间接参考的定性判断是：CrewAI 上手成本最低、LangGraph 编排能力最完整 [15]，但这属于定性评价而非基准测试结论。

## 四、典型场景适配

**复杂工作流自动化。** LangGraph 的状态机模型提供精确控制，适合业务流程自动化 [26]。若系统需要可审计、可回溯、带人工审批节点的生产级流程，LangGraph 是三者中唯一同时具备显式状态、检查点与 HITL 运行时机制的选项 [15][16]。

**快速原型与角色分工型任务。** CrewAI 的"角色-任务-流程"抽象上手成本最低，适合快速原型、内容生产、研究写作等角色分工明确的场景 [15][29]。Dify 和 Langflow 等可视化工具进一步降低开发门槛，适合极快速的概念验证 [26]；Dify 提供可视化应用搭建、Prompt 管理、知识库、工作流、模型接入与应用发布能力，适合快速构建企业内部 AI 助手、知识问答与低代码应用，但复杂后端集成、细粒度权限、高并发和深度定制需评估平台扩展边界 [27]。

**多角色协作研究。** AutoGen 强调多 Agent 之间的对话、分工与协作，适合探索复杂任务分解、代码生成、自动评审、研究助手和多角色协同流程，但更适合在实验和受控场景中验证任务分解方式；生产前需明确角色职责、工具权限、人工确认点、最大轮次与审计日志 [27]。多智能体系统整体上适合软件工程与开发自动化、复杂决策与协作、研究与知识型工作中的问题拆解（一个智能体收集信息、一个分析、一个整理输出）[28]。

**组合使用的实践模式。** 企业常在不同阶段组合使用：Dify 快速交付内部应用、LangChain 复杂后端编排、AutoGen 多 Agent 协作试验 [27]。LangChain 采用代码化编排，适合深度定制，但运行控制依赖团队自建日志、测试和监控，业务参与需要产品化界面承接 [27]。

## 五、2026 年趋势对选型前景的影响

**竞争逻辑已从"功能竞赛"转向"生态位锁定"。** 选型逻辑变成"你的场景是什么，就选对应的框架"，而非谁功能多选谁：LangGraph 锁定状态机/图编排（强流程控制、可审计的生产任务），CrewAI 锁定角色分工/团队协作（快速原型、内容生产、研究写作），Microsoft Agent Framework 锁定企业级多 Agent 编排（Azure/微软生态）[29]。

**协议标准化削弱框架壁垒。** MCP 已从 Anthropic 内部实验变成 Linux Foundation 下的行业标准，A2A 从 Google 提案变成 v1.0 正式协议；协议普及后 Agent 协作不再受限于特定框架或编程语言 [29][32]。协议支持度本身成为差异化维度：LangGraph 支持 MCP，PydanticAI 原生支持 MCP，Agno 支持 MCP，CrewAI 为社区适配，MetaGPT 使用内部协议 [34]。

**企业准入门槛抬高。** 2026 年框架若不具备 AgentOps 全链路治理、状态机与持久化、多代理零信任安全围栏三大支柱，就无法通过企业生产环境准入审计，这会抬高轻量框架进入企业市场的门槛 [34]。同时，全栈商用平台（面向中大型企业，内置治理、运维与多智能体协作）与开源底层框架（面向研发团队与轻量化场景，需自担治理运维成本）并行发展，竞争重心转向智能体全生命周期运营 [31][33]。

## 结论与建议

**总体结论：** 在 2026 年 11 月这个时点，三者的选型不是"三选一"的平面对比，而是"两个活跃主力 + 一个维护模式框架"的选择。AutoGen 的维护模式状态是硬约束，任何新项目立项都应首先排除它 [6][9]。

**按场景给出选择建议：**

1. **生产级复杂工作流自动化、需要审计与人工审批** → 选 **LangGraph**。理由：唯一具备显式状态机、检查点、interrupt/resume 运行时 HITL 机制与 LangSmith 全链路可观测性的方案，生产就绪度最高 [15][16][14]。预算上可参考 LangGraph Cloud $49/月单部署、$99/月五部署的定价 [6][7][8]。

2. **快速原型、内容生产、研究写作等角色分工明确的团队协作** → 选 **CrewAI**。理由：上手成本最低（10 行 Python 定义完整流程），已独立于 LangChain，具备 FedRAMP High、SSO 等企业能力，免费层 200 次 agent 运行/月足以支撑早期验证 [7][8][11][15]。需注意其顺序执行为主的流程模型难以处理动态分支或循环，复杂流程需评估 [1][2][3]。

3. **多角色对话式研究、代码生成与自动评审的实验性探索** → 若必须使用 AutoGen 生态，优先评估 **Microsoft Agent Framework 1.0**（官方推荐路径）或社区分支 **AG2**；后者虽活跃但生产就绪度被评为中低，不宜承载关键生产负载 [6][8][9][29]。

4. **企业内部低代码应用与知识问答快速交付** → 可考虑 **Dify** 等可视化平台，并与上述代码化框架分层组合：Dify 承接业务侧快速交付，LangGraph 承接复杂后端编排 [27]。

**需要提醒的决策风险：** 其一，社区规模数据在不同来源间差异显著（如 CrewAI stars 在 22K–57K 区间），不应作为主要决策依据，建议以官方仓库实时数据复核 [7][10][11]。其二，本报告在"性能基准、调试难度、学习成本"维度存在明确资料缺口，若这些指标对决策关键，需补充针对三个框架的同口径实测 [17]。其三，MCP/A2A 标准化正在降低框架锁定风险，长期看选型应更关注治理能力与生态位匹配，而非短期功能清单 [29][34]。
